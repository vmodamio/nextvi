10. Fixed live hard-wrap unwrapping after Backspace

User request:

> There is a flaw in the wrapping mechanism.  When the line wraps and the current word start in a new line, and then deleting characters with backspace until the word fits back in the previous line, leaves duplicated  characters on the screen

Assistant work:

- Reproduced a generated continuation row created by live hard wrapping.
- Found there was no symmetric live unwrap path: once `led_hardwrap_insert()` inserted `\n` plus `HWBRK`, Backspace could shorten the continuation but the generated row stayed until final reflow.
- Added `LED_HARDUNWRAP` and `led_hardwrap_unwrap()` in `led.c`.
- The unwrap path detects a generated `\nHWBRK` break before the current insert segment, checks whether the previous segment plus current segment fits within `conf_hwwidth`, removes the generated break, optionally restores the separator space, and deletes the old terminal row.
- Adjusted live insert segment baselines so generated continuation text remains deletable in the same insert session instead of being treated as protected pre-existing line content.
- Changed live and final hard-wrap width checks so `conf_hwwidth` is the maximum allowed visible width; wrapping now happens only when text exceeds that width.
- Verified with:
  `./cbuild.sh build`
- Ran a PTY smoke test:
  typed a line until a word moved to a generated continuation row, backspaced until the word fit on the previous row, confirmed the terminal deleted the generated row live, and confirmed the saved buffer was a single 39-column line.
- Committed C changes according to the standing commit rule.
- Commit:
  `9674203 Unwrap live hard wraps on backspace`
